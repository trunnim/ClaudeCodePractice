# 00 — Your first session

**นี่คือฉบับภาษาไทย** มีอีกสองฉบับที่เนื้อหาเหมือนกันทุกประการ:
[อังกฤษล้วน](./00-first-session.en.md) และ [สองภาษา](./00-first-session.bilingual.md)
อ่านครบทั้งสามฉบับแล้วเลือกโหมดที่ต้องการใน [`LANG.md`](./LANG.md)

หัวข้อหลักทั้งสี่ (Prerequisites, Try it, Check yourself, Common mistakes) คงเป็นภาษาอังกฤษไว้ทุกฉบับ
เพื่อให้เทียบกันได้ และเพื่อให้ `make docs` ตรวจได้

## Prerequisites

terminal หนึ่งตัว โฟลเดอร์ที่มีโค้ดอยู่ และ Claude subscription หรือ Anthropic API key
แค่นั้น บทเรียนนี้ตั้งสมมติฐานว่าคุณไม่เคยใช้ Claude Code มาก่อนเลย

## ติดตั้ง

```bash
curl -fsSL https://claude.ai/install.sh | bash      # macOS, Linux, WSL
```

Windows PowerShell ใช้ `irm https://claude.ai/install.ps1 | iex` ส่วน Homebrew ใช้
`brew install --cask claude-code`

## เริ่ม session

```bash
cd ClaudeCodePractice
claude
```

ครั้งแรกจะให้ล็อกอินก่อน สิ่งที่คุณได้คือ **session** — บทสนทนาต่อเนื่องหนึ่งชุด
ที่มีประวัติเป็นของตัวเอง ปิดไปแล้วกลับมาต่อได้

session ไม่ใช่แค่หน้าต่างแชท มันคือพื้นที่ทำงานที่มีความจำ ทุกอย่างที่เกิดขึ้นในนั้น — ไฟล์ที่อ่าน
คำสั่งที่รัน บทสนทนาทั้งหมด — สะสมอยู่ข้างใน และไม่หายไปเอง
นี่คือเหตุผลว่าทำไมงานคนละเรื่องควรอยู่คนละ session ซึ่งเป็นหัวใจของบทเรียนที่ 02

## ลองถามอะไรสักอย่าง

พิมพ์ข้อความนี้แล้วกด Enter:

```text
what does this repository do? don't change anything yet
```

สังเกตสิ่งที่ปรากฏขึ้น Claude ไม่ได้ตอบทันที — มันไล่ดูรายชื่อไฟล์ อ่านไปสองสามไฟล์ แล้วค่อยตอบ
การกระทำแต่ละครั้งนั้นคือ **tool call** และคุณเห็นมันทุกครั้งที่เกิดขึ้น

วงจรนี้เรียกว่า **agentic loop**: คิด → ลงมือ → อ่านผลลัพธ์ → คิดใหม่ วนไปจนกว่างานจะเสร็จหรือจนกว่ามันจะต้องถามคุณ

**ทำไมถึงสำคัญ:** นี่คือความต่างที่แท้จริงระหว่าง Claude Code กับ chatbot
chatbot ตอบจากสิ่งที่คุณพิมพ์ให้ แต่ Claude Code ไปหาข้อมูลเองได้ และเห็นผลลัพธ์ของการกระทำตัวเอง
ผลที่ตามมาสำคัญมาก: ถ้าคุณให้คำสั่งที่มันรันเองแล้วรู้ผลได้ เช่น `pytest` มันจะวนแก้เองจนคำสั่งนั้นผ่าน
แต่ถ้าไม่มี มันจะหยุดตอนที่งาน "ดูเหมือน" เสร็จ แล้วปล่อยให้คุณเป็นคนตรวจเอง
บทเรียนที่ 05 ว่าด้วยเรื่องนี้ทั้งบท

อ่าน tool call ด้วย อย่าอ่านแต่คำตอบสุดท้าย เพราะมันเป็นทางเดียวที่จะรู้ว่า Claude **ทำอะไรลงไปจริง ๆ**
ไม่ใช่แค่สิ่งที่มันบอกว่าทำ

## permission prompt ครั้งแรกของคุณ

คราวนี้ลองสั่งให้แก้ไฟล์:

```text
add a line to practice/lesson-00-notes.md saying "hello from lesson 00"
```

Claude จะหยุดถามก่อนเขียน นั่นคือ **permission prompt** — มันจะขึ้นก่อนทุกอย่างที่กระทบเครื่องคุณ
ไม่ว่าจะเขียนไฟล์ รันคำสั่ง Bash หรือเรียกเครื่องมือภายนอก

อ่านสิ่งที่มันเสนอ แล้วค่อยอนุมัติ

**ทำไมถึงสำคัญ:** จุดนี้คือด่านตรวจสุดท้ายของคุณ และเป็นจุดที่คนส่วนใหญ่เสียการควบคุมโดยไม่รู้ตัว
พออนุมัติไปสิบครั้ง คุณจะเริ่มกดผ่านโดยไม่อ่าน ซึ่งเท่ากับไม่มีด่านตรวจเลย
ทางแก้ไม่ใช่การพยายามตั้งใจอ่านให้มากขึ้น แต่คือการอนุญาตคำสั่งที่ปลอดภัยไว้ล่วงหน้า
เพื่อให้ครั้งที่มันถามจริง ๆ มีความหมาย บทเรียนที่ 01 จะพาไปดูวิธี

## สี่อย่างที่ต้องรู้ก่อนปิด

อะไรที่ขึ้นต้นด้วย `/` คือ **slash command** พิมพ์ลงไปใน session ได้เลย:

| | |
|---|---|
| `/help` | ทุกอย่างที่ใช้ได้ในเวอร์ชันของคุณ |
| `/context` | ตอนนี้มีอะไรโหลดอยู่บ้าง รวมถึงไฟล์คำสั่งที่ Claude อ่านไป |
| `/clear` | ล้างบทสนทนาแล้วเริ่มใหม่ โดยไม่ต้องออกจากโปรแกรม |
| `Esc` | หยุด Claude กลางคัน มันหยุดจริง และบทสนทนายังอยู่ครบ |

กด `Ctrl+C` สองครั้งเพื่อออก session ถูกบันทึกไว้ กลับมาต่อด้วย `claude --continue`

**ทำไมถึงสำคัญ:** `Esc` คือปุ่มที่มือใหม่ใช้น้อยเกินไป ถ้าเห็นว่า Claude กำลังไปผิดทางให้หยุดทันที
อย่ารอให้มันทำจนจบแล้วค่อยบอกว่าผิด เพราะทุกอย่างที่มันทำระหว่างนั้นค้างอยู่ใน session
และไปรบกวนงานถัดไป การแก้ให้ถูกทางเร็ว ๆ ได้ผลดีกว่าปล่อยแล้วแก้ทีหลังเสมอ

## Try it

1. เปิด session ใน repository นี้
2. ถามว่า `what does this repository do? don't change anything yet`
3. รัน `/context` แล้วหาบรรทัดที่ระบุ **Memory files**
4. สั่งให้ Claude เขียนคำตอบของสามคำถามนี้ลงใน `practice/lesson-00-notes.md`:
   - Claude อ่านไฟล์อะไรบ้างก่อนตอบ และกี่ไฟล์
   - `/context` บอกว่ามี memory file อะไรโหลดอยู่บ้าง
   - permission prompt ขออนุมัติอะไร เขียนมาแบบคำต่อคำ
5. อนุมัติการเขียนไฟล์
6. รัน `/clear` แล้วถามว่า `what did I just ask you?`

## Check yourself

```bash
make progress      # lesson 00 ควรขึ้น [x]
```

ถือว่าผ่านเมื่อ: `practice/lesson-00-notes.md` มีอยู่จริงพร้อมคำตอบทั้งสามข้อ, `/context` แสดง
`CLAUDE.md` ใต้หัวข้อ **Memory files**, และหลัง `/clear` แล้ว Claude จำไม่ได้เลยว่าคุณถามอะไรไป
เพราะ `/clear` ลบบทสนทนาทิ้งจริง ๆ

ตอนที่เปิด `/context` อยู่ ลองสังเกตด้วยว่า `PROFILE.md` ขึ้นเป็นรายการแยกของตัวเองหรือเปล่า
`CLAUDE.md` import มันเข้ามา และการ import คือการ **แทรกเนื้อหาเข้าไปในไฟล์ที่ import**
ดังนั้นมันอาจไม่ขึ้นเป็นรายการแยก ทั้งที่เนื้อหาถูกโหลดแล้ว จดไว้ว่าคุณเห็นแบบไหน

**ทำไมถึงสำคัญ:** จุดนี้เป็นตัวอย่างเล็ก ๆ ของนิสัยที่สำคัญมาก — ตรวจสอบเอง อย่าเชื่อเอกสาร
(รวมถึงบทเรียนนี้ด้วย) `/context` บอกความจริงว่ามีอะไรโหลดอยู่ ส่วนสิ่งที่คุณ *คิดว่า* โหลดอยู่ เป็นคนละเรื่องกัน
ความต่างระหว่างสองอย่างนี้คือที่มาของปัญหา "ทำไม Claude ไม่ทำตามที่เขียนไว้" เกือบทั้งหมด

ถ้าผลของ `/clear` ทำให้คุณแปลกใจ ถือว่าดี — นั่นคือบทเรียนที่ 02

## Common mistakes

**อ่านแต่คำตอบสุดท้าย ไม่ดู tool call** — เป็นนิสัยที่ติดมาจากการใช้ chatbot และเป็นสาเหตุอันดับหนึ่งของปัญหา
"Claude บอกว่าแก้แล้วแต่มันไม่ได้แก้" ถ้าอ่าน tool call คุณจะเห็นเองว่ามันแก้ไฟล์ไหนจริง ๆ

**กด approve รัว ๆ โดยไม่อ่าน** — permission prompt มีค่าเท่ากับความตั้งใจที่คุณใส่ลงไปในการอ่านมัน
ถ้ากดผ่านทุกอันโดยอัตโนมัติ ก็ไม่ต่างจากปิดมันทิ้ง

**คิดว่า `/clear` เหมือนล้างหน้าจอ** — มันไม่ใช่คำสั่ง `clear` ของ terminal
มันลบความจำของบทสนทนาทิ้งจริง ๆ ซึ่งเป็นสิ่งที่คุณต้องการเมื่อเปลี่ยนไปทำงานเรื่องใหม่ แต่จะเจ็บมากถ้าเผลอกดกลางงาน

**ไม่ยอมกด `Esc`** — มือใหม่มักปล่อยให้ Claude ทำจนจบทั้งที่รู้ว่าผิดตั้งแต่ต้น เพราะรู้สึกเหมือนไปขัดจังหวะ
แต่ context ที่เสียไปกับทางที่ผิดไม่ได้หายไปไหน มันอยู่กับคุณไปตลอด session

**เปิด session เดียวทำทุกเรื่อง** — เป็นข้อผิดพลาดที่พบบ่อยที่สุด และเป็นเรื่องของบทเรียนที่ 02
